# Reconstruction architecture

- **Execution:** Android and desktop call shared `generateLocal` with installed model files. Model acquisition is separate from reconstruction. The reconstruction session retains validated pre-simplification geometry and calibrated views. It creates an unrigged result first, then independently builds requested rig variants from the retained data without rerunning camera/depth inference. Each variant retains its own geometry, atlas, rig and exact GLB. The preview rasterizes the same geometry and UV atlas with independent wireframe and skeleton overlays.
- **Interactive Colab:** the optional headless desktop entry point calls the same engine and writes the unrigged GLB before attempting independent rig variants. The notebook opens in the user's browser; it is not an app-hosted remote API. See [Colab](COLAB.md).
- **Single engine:** shared JVM source is compiled into both Android and desktop targets, with platform-specific native runtime artifacts and document IO. The common geometry and rig modules are not duplicated.
- **Foreground:** optional U²-Net portable segmentation runs before DA3, bypassing existing alpha masks. Original RGB stays available for camera alignment; learned alpha controls surface samples and silhouette carving. Flat or effectively empty predictions fail explicitly. The segmentation session closes before DA3 opens.
- **Camera consistency:** DA3 four-view graph emits depth, confidence, intrinsics and world-to-camera matrices in one shared coordinate system. Overlapping windows are aligned with a median log-depth scale and a camera-derived similarity transform. Inconsistent shared camera poses or depths fail explicitly; overlapping references are retained once. Projective TSDF fuses those predictions; alpha masks carve visible background. Robust bounds and a finite cubic voxel grid limit memory. The mesh-detail slider sets the number of cells along each grid axis, not the image dimensions or texture size; the field stores one additional sample along each axis. Marching tetrahedra extracts an indexed mesh. First camera coordinates determine upright output; height is normalized to one unit. The reconstruction frame retains inverse first-camera normalization and voxel spacing for downstream reprojection.
- **Surface topology:** the shared generation path removes duplicate and degenerate faces, reconciles adjacent face winding, caps only small convex planar boundary loops, and verifies closed edge incidence and single-cycle vertex links before skinning/export. Disconnected shells are preserved. After repair, a shared bounding-volume hierarchy and double-precision separating-axis test reject non-adjacent triangle intersections, including coplanar overlap. The test deliberately excludes pairs sharing a vertex and uses scale-relative tolerance; it is not an exact or complete geometric validator. Animation-quality topology is not guaranteed.
- **Adaptive simplification:** after repair and non-adjacent intersection validation, bounded local edge collapses reduce redundant flat-region triangles. Sharp normal changes, color boundaries, the closed-manifold link condition, face orientation and accumulated representative displacement constrain collapse. The candidate must pass topology and non-adjacent intersection checks without additional repairs; otherwise the original validated mesh is exported. For rigged output, the provisional T-pose joints are established on the repaired mesh before simplification. Protected joint neighborhoods and their incident triangles are excluded from edge collapses, and the same skeleton binds the final mesh. Protection uses bounded bone-length-based radii, not measured deformation or learned anatomy. This preserves the existing mesh when optimization is unsafe; it does not create deformation-oriented edge loops or quads.
- **Texture export:** a shared JVM stage bakes depth-consistent photographic samples into padded per-triangle charts in an sRGB PNG, with a 4096-pixel side cap. Export-only UV seam vertices inherit original smooth normals and skin weights. The GLB embeds the PNG and uses a non-mipmapped linear sampler to avoid cross-chart bleeding. If the atlas exceeds the budget, export preserves vertex colors. Before baking, up to 2048 face centers provide depth-checked overlapping RGB samples. Dark, clipped and chromatically inconsistent samples are rejected; robust pairwise exposure ratios constrain an anchored weighted log-space graph solve. Gains are bounded to one stop; disconnected views retain independent exposure anchors. Interpolated vertex-color fallback is not exposure-corrected. Each triangle selects up to three calibrated cameras by confidence, front-facing angle and depth agreement at its center and corners. Each texel rechecks depth within two original voxel widths and bilinear foreground coverage, blending eligible RGB samples in linear color space. Missing coverage falls back to vertex colors. Sources are the resampled 504-pixel grids, not full-resolution originals; this is approximate visibility, not a ray-traced occlusion guarantee. White balance, local lighting correction, efficient chart packing and higher-resolution sources remain future work.
- **Template rigging:** Template joints are experimental and suitable only for a T-pose starting point. Each joint seeds its nearest surface vertex; weighted mesh-edge shortest paths propagate influence within the connected component. Up to four inverse-fourth-power distance weights are normalized per vertex. Components with no joint seed bind rigidly to their nearest joint. The method prevents propagation across disconnected surfaces but may still misassign seed vertices or bleed along unintended mesh bridges. It is not volumetric or learned skinning. A GLB skin is not proof of animation-quality deformation.
- **Learned rigging:** optional shared JNI bridge calls the pinned C++ SkinTokens in-memory API and validates hierarchy and four weights per original vertex before texture baking and GLB export, so native model memory is released before allocating the atlas. Learned mode skips pre-inference simplification because joint locations are not known beforehand. After inference, a bounded shared bend-refinement stage attempts small transfers between existing learned influences only when all sampled single-subtree coordinate-axis rotations have non-increasing incident squared edge strain and worst strain. Long high-gradient edges may be split conformingly at their midpoints, with at most one split per face, preserved rest surface, interpolated colors and bounded four-weight mass loss. The split is accepted only if its new edges do not exceed the original local worst sampled strain; topology and intersections are revalidated before texture baking. The current atlas tile-size tier is preserved. This is conservative adaptive triangle refinement, not full quad retopology, a volume-preserving skin solver or a guarantee for combined poses. Large meshes beyond the mobile work bounds retain the original rig. Explicit selection, native ABI check, immutable release pins, staged checksum-verified bundle acquisition and pre-inference re-verification are required. No silent template fallback. The shared source contains verified publisher weight pins; ordinary builds still omit the optional native binaries. The five native validation packaging lanes passed in run 45716980363. An opt-in Linux model-backed smoke test uses the production downloader, learned rig, and textured exporter, with a synthetic deformation diagnostic. Linux real-model inference and textured export passed in run 45720151565. The new test retains exact synthetic GLB and paired rest/pose visual diagnostics; the baseline visual inspection in run 45723627847 found a plausible skeleton but substantial torso distortion. Refined output comparison, installed app startup and device inference remain release gates. See [native integration](SKINTOKENS.md).
- **Input and resource limits:** the graph is downloaded or imported and verified, 4–24 ordered overlapping views are supported through fixed four-view inference windows, and generation speed depends on local RAM and CPU. Device performance remains to be measured.

## Next implementation gates

1. Run Android, Windows, macOS, Linux and Chromebook smoke tests; measure peak RAM and runtime.
2. Validate surface and skin output against independently generated known-camera fixtures and glTF Validator.
3. Validate checksum-verified model acquisition on every platform; ship model license notices and reproducible export.
4. Validate overlapping-window alignment with real DA3 captures; improve drift correction and scale to larger reference sets.
5. Validate neural foreground masks on photographs and character art; validate conservative surface repair on reconstructed meshes; validate joint-aware planar simplification and protected incident triangles; implement deformation-oriented edge loops and quad retopology, adjacency-aware self-intersection detection, efficient UV chart packing, full-resolution source-image texture reprojection, white balance and local lighting correction; validate current exposure matching, photographic baking and embedded atlas export.
6. Validate surface-distance skinning with deformation fixtures; verify native learned skeleton and skin estimation on every platform, validate pinned model downloads and package native libraries, creature/mechanical rig modes, animation/deformation review.
7. Optional local image generation, GPU acceleration, editable 3D preview.

No gate is marked complete without runtime evidence.
