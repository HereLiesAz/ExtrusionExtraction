# Colab (experimental interactive workflow)

The notebook is optional, not an execution replacement. Free managed Colab prohibits using it as a hidden application backend; see the [FAQ](https://research.google.com/colaboratory/faq.html). Use a user-controlled notebook, not an app-side web UI, tunnel, unattended worker or automated runtime pool. No billing integrations or paid fallbacks are provided.

The [notebook](../notebooks/ExtrusionExtraction.ipynb) runs the desktop JVM engine headlessly, with the same decoder, model verification, reconstruction and independent rig variants. Existing local Android and desktop execution stays intact. The notebook downloads the newest published versioned Linux x86_64 worker (or an explicitly selected build), verifies the GitHub asset SHA-256 and exact length, safely extracts it and checks ONNX/SkinTokens initialization before uploading references. No Gradle, compiler, JDK installation, Android SDK or Compose is required in Colab. In the app, arrange references, select mesh detail and masking, choose either or both remote rig variants, and export a .eejob file. Upload that single file to the notebook and explicitly run the reconstruction cell; it carries the exact inference pixels and settings, without names or credentials. Alternatively upload individual images and specify their order manually. Download reconstruction.eeresult and use Import Colab result in the Android or desktop workspace. Switch between completed rig variants, inspect the actual textured geometry and export the original GLBs. Standalone GLBs remain downloadable. Android requests a browser-owned expandable Custom Tab; desktop opens the default browser. Experimental app-owned OAuth and API file transfer are available for a paired, user-operated notebook. Web integration is not implemented. Runtime expiration loses temporary files. No automatic retries or fallback are attempted.

Validation gates: Linux build, desktop regressions, model-backed GLBs, parity with desktop, actual free Colab memory/runtime and SkinTokens native toolchain, cold GLEE review. GPU acceleration and integrated remote execution remain unvalidated. If a learned model fails during the job, the base and successful template export remain available if reconstruction succeeds. The initial worker check requires the packaged native runtime to load.

## Job format EEJ1

Four big-endian 32-bit integers: ASCII EEJ1 (0x45454a31), mesh cells, flags (bit 0 foreground mask, bit 1 template rig, bit 2 learned rig), reference count. Followed by ordered 504×504 big-endian ARGB32 grids. No filenames, code or credentials. Only 4–24 references and 32–96 cells are accepted. Unknown bits, trailing bytes and truncation are rejected before image arrays are allocated. The JVM worker validates the job again regardless of notebook validation. Exporting a job requires no installed local model and never uploads automatically.

## Headless build

From the repository root, run `./gradlew -p headless test` for orchestration and job-format tests, or `./gradlew -p headless run --args="--job /absolute/models /absolute/new-output /absolute/reconstruction.eejob"` for an actual reconstruction. Add `-PskinTokensNativeDir=/absolute/native-stage` when the native runtime has been built. This build directly compiles the shared non-UI and desktop headless sources, rather than maintaining a second implementation. Keep its Kotlin, ONNX Runtime and coroutine dependency versions synchronized with the main build. Android and desktop application builds continue using their existing Gradle configuration.

## Precompiled release worker

CI runs `bash scripts/package_colab_worker.sh /absolute/output/colab-worker-linux-x86_64.tar.gz` with JDK 17 and a C++23 compiler. It compiles the shared engine and native libraries, runs the notebook and headless tests, bundles a Java runtime and compiler libraries, and smoke-checks the archive after extraction. The central release publisher stages it as `ExtrusionExtraction-vMAJOR.MINOR.PATCH.BUILD-colab-linux-x86_64.tar.gz` alongside existing installers and includes it in the release checksum manifest. Model weights remain separately downloaded from immutable pins. The notebook uses GitHub's published SHA-256 asset metadata, not arbitrary user-provided package URLs. The worker requires compatible Linux x86_64, glibc and CPU; runtime portability has not yet been demonstrated on actual Colab. No paid services are invoked by the notebook.

## Result format EER1

The headless worker publishes `reconstruction.eeresult` after every successful variant, atomically replacing it only when the expanded bundle is complete. The unrigged result is mandatory. Standalone GLBs survive bundle failures. The envelope uses big-endian magic EER1, a 32-bit variant count, then per variant a 32-bit ID (0 unrigged, 1 template, 2 learned), 64-bit byte length and the existing desktop model packet (positions, colors, indices, optional joints and weights, optional per-corner UVs and RGB PNG, exact GLB). Limits: 256 MiB per packet, 512 MiB per envelope, one million vertices, six million indices, 1024 joints and 4096-pixel square atlas. The importer validates lengths before allocation, finite geometry, hierarchy, normalized weights, PNG dimensions, UVs and exact GLB consistency with the packet's preview data. EER1 requires the same exporter contract; incompatible future exporters must use a new format version. Import is all-or-nothing. Imported variants have no live reconstruction session, so missing variants must be generated in Colab; existing local generation and rigging are unchanged. An older release may still produce only GLBs until a new worker is published.

## Live notebook browser surface

The Colab workspace card opens the canonical notebook at colab.research.google.com, with Google's real controls and output. Android requests a resizable partial Custom Tab (bottom sheet on phones, side sheet on supported wide screens), using the browser's own account session and cookies. Browser support determines whether the tab is partial or full-screen; the app cannot detect the resulting layout. If a Custom Tabs provider is missing or cannot launch, the app opens an ordinary browser. The explicit Open in browser action bypasses the panel. On desktop the browser tab is external, not an embedded view. These choices preserve the trusted browser origin and avoid WebView-based Google authentication; see [Custom Tabs](https://developer.chrome.com/docs/android/custom-tabs/guide-partial-custom-tabs) and [Google OAuth policy](https://developers.google.com/identity/protocols/oauth2/policies). The card reports launch dispatch or failure only, not authentication, runtime connection, or execution progress. Use the existing browser tab to resume a running notebook; opening the canonical link again may create another tab or notebook. Dismissing the browser does not cancel a runtime. Job export/result import remain explicit and local execution is unchanged. Device/browser sign-in, partial-tab behavior, uploads and downloads require real Android/browser testing.

## Experimental Google-authorized file transfer

The app uses the official Colab REST API (`https://colaboratory.googleapis.com/v1beta/runtimes`) and runtime proxy's Jupyter contents/files endpoints. It never allocates, deletes or executes a runtime through the API. Run the actual notebook's pairing cell, authorize the Colab scope in the app, select the existing runtime, paste the one-time pairing code, pair, send a job, set USE_API_TRANSFER=True in the upload cell and explicitly run the notebook. Retrieve the completed result in the app. The pairing marker proves that the selected runtime contains the notebook-created directory; no account email or broader scopes are requested. Each pairing accepts one job; create a fresh pairing for another. Uploads use unique filenames, and the notebook rejects multiple pending submissions rather than selecting one or overwriting it. Manual job and result files remain available. The app refreshes the proxy token via runtimes.get before each operation, never follows redirects, and sends Google OAuth tokens only to the fixed control-plane host. Access tokens are not written to disk or logged. Disconnect clears app-held credentials; it does not revoke Google's grant or terminate the runtime.

**Deployment prerequisites:** enable the Colab API in a Google Cloud project, register the Android OAuth client for application ID com.hereliesaz.extrusionextraction and each actual signing certificate SHA-1 (debug/release/Play as applicable), configure OAuth consent and test users or production verification. Android uses Google Identity Services; devices without Google Play services retain manual transfer. Desktop requires a registered installed-app OAuth client via EE_COLAB_DESKTOP_CLIENT_ID and, if required by that client, EE_COLAB_DESKTOP_CLIENT_SECRET in the launch environment. These are app client identifiers, not developer Google account tokens. Desktop uses the system browser, loopback callback, PKCE and state; no offline grant. Public release configuration, actual runtime proxy hostname/route behavior, free-tier API eligibility and real account testing are still required. No paid fallback, billing setup or developer compute is introduced. References: [Colab REST API](https://developers.google.com/colab/api/reference/rest), [runtime file transfer](https://developers.google.com/colab/api/reference/mcp/tools_list/get_runtime), [Android authorization](https://developer.android.com/identity/authorization), [desktop OAuth](https://developers.google.com/identity/protocols/oauth2/native-app). The free-runtime FAQ still governs usage; no UI bypass or unattended execution is provided.
