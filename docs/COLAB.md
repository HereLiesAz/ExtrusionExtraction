# Colab (experimental interactive workflow)

The notebook is optional, not an execution replacement. Free managed Colab prohibits using it as a hidden application backend; see the [FAQ](https://research.google.com/colaboratory/faq.html). Use a user-controlled notebook, not an app-side web UI, tunnel, unattended worker or automated runtime pool. No billing integrations or paid fallbacks are provided.

The [notebook](../notebooks/ExtrusionExtraction.ipynb) runs the desktop JVM engine headlessly, with the same decoder, model verification, reconstruction and independent rig variants. Existing local Android and desktop execution stays intact. Supply a reviewed commit SHA and install the prerequisites. In the app, arrange references, select mesh detail and masking, choose either or both remote rig variants, and export a .eejob file. Upload that single file to the notebook and explicitly run the reconstruction cell; it carries the exact inference pixels and settings, without names or credentials. Alternatively upload individual images and specify their order manually. GLB exports can be downloaded from the notebook; the shared workspace opens the actual notebook in the system browser. Embedded authentication, automatic transfer, direct app import and web integration are not implemented. Runtime expiration loses temporary files. No automatic retries or fallback are attempted.

Validation gates: Linux build, desktop regressions, model-backed GLBs, parity with desktop, actual free Colab memory/runtime and SkinTokens native toolchain, cold GLEE review. GPU acceleration and integrated remote execution remain unvalidated. If a native build or learned model fails, the base and successful template export remain available if reconstruction succeeds.

## Job format EEJ1

Four big-endian 32-bit integers: ASCII EEJ1 (0x45454a31), mesh cells, flags (bit 0 foreground mask, bit 1 template rig, bit 2 learned rig), reference count. Followed by ordered 504×504 big-endian ARGB32 grids. No filenames, code or credentials. Only 4–24 references and 32–96 cells are accepted. Unknown bits, trailing bytes and truncation are rejected before image arrays are allocated. The JVM worker validates the job again regardless of notebook validation. Exporting a job requires no installed local model and never uploads automatically.
