# Native learned rigging (experimental, release-gated)

The pinned [SkinTokens C++23/GGML runtime](https://github.com/localai-org/skin-tokens.cpp/tree/43aac7b0fe45f5cd802365e6964c13bfc5e5fb52) is Apache-2.0; the [F16 GGUF weights](https://huggingface.co/LocalAI-io/SkinTokens-GGUF) are MIT-labelled. The upstream C++ API returns a skeleton and four influences per input vertex without round-tripping a GLB. Our original indexed mesh, UV atlas and exporter remain authoritative. The initial backend is CPU with one beam; this is a chosen portability baseline, not a demonstrated speed or quality target.

## Build and acquire

From the repository root, run `python scripts/build_skintokens.py` on each desktop host. It fetches exact runtime, GGML and nlohmann-json source revisions into the ignored build directory, rejects changed checkouts, installs the JSON headers/config, builds the JNI target and stages only its runtime libraries plus SkinTokens/GGML license notices. Use `python scripts/build_skintokens.py --prepare-only` before Android packaging; this prepares the same sources and prints the Gradle arguments. The script does not download model weights. The [central native package validation profile](https://github.com/HereLiesAz/workflows/pull/226) calls this entry point on main-branch pushes and manual dispatch. It stages validation artifacts for Linux, Windows, Intel and Apple Silicon macOS, and Android/ChromeOS (ARM64 and x86-64). It does not publish releases. Ordinary builds without native build arguments still omit the runtime.

Offline dependency-staging regression: `python -m unittest discover -s scripts -p test_build_skintokens.py`. The test uses real temporary Git repositories to exercise a successful pinned fetch, reusable clean checkout, wrong revision, dirty checkout and failed-fetch cleanup. It does not compile upstream.

Build validation: [the first central matrix](https://github.com/HereLiesAz/workflows/actions/runs/45665940114) successfully compiled and staged the actual pinned native runtime on Linux and Intel macOS. Gradle rejected the zero-major DMG version during configuration, including on Linux and Android; Windows compilation failed on MSVC's C4996 diagnostic for the upstream std::getenv profiling flag. Apple Silicon was cancelled. The build now uses a macOS-specific positive installer major (product major + 1) and a target-scoped MSVC CRT compatibility definition; the product version and pinned source checkout remain unchanged. The [second central matrix](https://github.com/HereLiesAz/workflows/actions/runs/45716980363) compiled and packaged all five targets successfully, with both requested Android ABIs checked in the APK. This establishes compilation and artifact creation, not model inference, installer launch or physical-device compatibility.


- Obtain the runtime at the pinned commit, including its pinned GGML submodule; CMake rejects a different HEAD. Provide CMake 3.25+ and nlohmann-json 3.11+, and a compiler supporting C++23 std::expected. The Android lane requires the NDK and CMake versions declared in shared/build.gradle.kts and an Android-compatible nlohmann-json CMake package.
- Android and ChromeOS: configure Gradle with -PskinTokensSource=/absolute/pinned/checkout. The optional external native build targets arm64-v8a and x86_64. If nlohmann-json is not on the CMake search path, pass -PskinTokensJsonDir=/absolute/nlohmann-json-config-directory.
- Desktop: configure native/skintokens with -DSKINTOKENS_SOURCE_DIR=/absolute/pinned/checkout, build target ee_skintokens, and install component ee_runtime to a staging root. Package using -PskinTokensNativeDir=/absolute/staging/root. The common folder contains both native libraries. Build and test separately for each target host and architecture.
- Both platforms compile the fixed F16 identities in SkinTokensBundle.kt. The [publisher's verified checksum commit](https://huggingface.co/LocalAI-io/SkinTokens-GGUF/commit/2c55d38ffe01871c6956103926cc4a40bd7acc8a), its MANIFEST.json and individual file SHA256 metadata agree on all three digests. The total is 1,250,390,624 bytes. See [model provenance](MODEL_PROVENANCE.md). No build-time override or runtime trust-on-first-use is accepted.
- With a compatible packaged native runtime, the shared UI offers explicit F16 download. A complete staging bundle is verified for exact length and SHA-256 while downloading, then atomically published; both checks are repeated before native inference. File-size readiness is not a substitute for verification. A damaged installed bundle must be removed before reinstallation. Upstream also validates embedded source identities. No downloaded native executable is used.
- Select learned rigging explicitly. Errors fail generation rather than silently substituting the humanoid template. Native inference is synchronous and cancellation is checked before and after it, not inside upstream inference. Generated joint names are stable synthetic identifiers; the current exporter supports a single root and parent-first, translation-only rest positions.

The JNI bridge compiled and ran on a Linux JVM using a mock implementation of the inspected upstream interface; packet validation passed one valid fixture and ten invalid-packet cases. This does not validate GGML linking or model-backed inference. The shared streaming verifier passed isolated Kotlin fixtures for a known SHA-256, short/long input, wrong digest, cancellation, and exact file-size readiness. The real GGUF download and Linux inference passed in [run 45720151565](https://github.com/HereLiesAz/workflows/actions/runs/45720151565). Actual peak RAM, installed application startup and physical Android/ChromeOS/desktop parity remain unverified. The upstream C++ API requires C++23; NDK standard library support must be confirmed. This integration is not release-ready. Include upstream runtime and GGML license notices and weight provenance in production installers before enabling this lane.

## Model-backed validation

Run `./gradlew :shared:desktopTest -PskinTokensNativeDir=../build/skintokens/host-install` after the native build. The central Linux packaging lane already supplies that property. The integration test must load the actual staged JNI libraries, explicitly download and verify the pinned model bundle into a temporary directory, recheck it during learned inference, and verify the articulated rig and textured GLB. Ordinary unit tests do not download weights. The fixture is a closed voxel humanoid with independently specified topology. A non-root subtree rotation reports displacement and edge-length ratios; structural checks are not a visual or anatomical quality claim. The test validates source vertex and weight correspondence across UV seams and exact embedded image bytes. The temporary model bundle is removed after the test. The first real-model run passed: 12 predicted joints, 9.030652109 seconds download/verification, 224.48601861 seconds verification/inference, 42,048-byte GLB. A 90-degree non-root subtree rotation produced maximum displacement 0.74168277 normalized units and edge-length ratios 0.42937893 to 1.737988. These are runner-specific structural measurements, not an anatomical assessment.

The test now retains the exact generated GLB and a front/oblique rest/pose SVG with common framing, triangle edges and X-ray joint overlays in `shared/build/reports/skintokens/`. The synthetic outputs are also encoded in the Linux job log as `EE_RIG_DIAGNOSTIC` headers and numbered `EE_RIG_DATA` chunks (gzip/base64). Concatenate chunks in numerical order for each filename, decode base64, decompress gzip, and verify the original byte count and SHA-256 before inspection. The visual renderer uses centroid depth ordering, not exact visibility; this does not modify generation or ship test assets in installers. New visual outputs must still be inspected.

## AssetFurnace comparison

[AssetFurnace](https://assetfurnace.com/llms.txt) is a complementary reference implementation for multi-backend orchestration, cleanup, pixel-preserving projection, rigging, animation presets and per-output model-license provenance. It advertises Apple Silicon and NVIDIA Linux, limited Windows testing, Python and Blender for finishing; it is not an Android/ChromeOS dependency. Its MCP installation instructions are for local agent clients, not instructions to execute an installer in this app. Evaluate reusable algorithms separately, with license review and portable execution requirements; no AssetFurnace runtime, cloud service or weights have been added.
