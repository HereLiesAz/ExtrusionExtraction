# Native learned rigging (experimental, release-gated)

The pinned [SkinTokens C++23/GGML runtime](https://github.com/localai-org/skin-tokens.cpp/tree/43aac7b0fe45f5cd802365e6964c13bfc5e5fb52) is Apache-2.0; the [F16 GGUF weights](https://huggingface.co/LocalAI-io/SkinTokens-GGUF) are MIT-labelled. The upstream C++ API returns a skeleton and four influences per input vertex without round-tripping a GLB. Our original indexed mesh, UV atlas and exporter remain authoritative. The initial backend is CPU with one beam; this is a chosen portability baseline, not a demonstrated speed or quality target.

## Build and acquire

- Obtain the runtime at the pinned commit, including its pinned GGML submodule; CMake rejects a different HEAD. Provide CMake 3.25+ and nlohmann-json 3.11+, and a compiler supporting C++23 std::expected. The Android lane requires the NDK and CMake versions declared in shared/build.gradle.kts and an Android-compatible nlohmann-json CMake package.
- Android and ChromeOS: configure Gradle with -PskinTokensSource=/absolute/pinned/checkout. The optional external native build targets arm64-v8a and x86_64. If nlohmann-json is not on the CMake search path, pass -PskinTokensJsonDir=/absolute/nlohmann-json-config-directory.
- Desktop: configure native/skintokens with -DSKINTOKENS_SOURCE_DIR=/absolute/pinned/checkout, build target ee_skintokens, and install to a staging root. Package using -PskinTokensNativeDir=/absolute/staging/root. The common folder contains both native libraries. Build and test separately for each target host and architecture.
- Both platforms compile the fixed F16 identities in SkinTokensBundle.kt. The [publisher's verified checksum commit](https://huggingface.co/LocalAI-io/SkinTokens-GGUF/commit/2c55d38ffe01871c6956103926cc4a40bd7acc8a), its MANIFEST.json and individual file SHA256 metadata agree on all three digests. The total is 1,250,390,624 bytes. See [model provenance](MODEL_PROVENANCE.md). No build-time override or runtime trust-on-first-use is accepted.
- With a compatible packaged native runtime, the shared UI offers explicit F16 download. A complete staging bundle is verified for exact length and SHA-256 while downloading, then atomically published; both checks are repeated before native inference. File-size readiness is not a substitute for verification. A damaged installed bundle must be removed before reinstallation. Upstream also validates embedded source identities. No downloaded native executable is used.
- Select learned rigging explicitly. Errors fail generation rather than silently substituting the humanoid template. Native inference is synchronous and cancellation is checked before and after it, not inside upstream inference. Generated joint names are stable synthetic identifiers; the current exporter supports a single root and parent-first, translation-only rest positions.

The JNI bridge compiled and ran on a Linux JVM using a mock implementation of the inspected upstream interface; packet validation passed one valid fixture and ten invalid-packet cases. This does not validate GGML linking or model-backed inference. The shared streaming verifier passed isolated Kotlin fixtures for a known SHA-256, short/long input, wrong digest, cancellation, and exact file-size readiness. The real GGUF download, full native compilation, actual peak RAM, packaging, and physical Android/ChromeOS/desktop parity are unverified. The upstream C++ API requires C++23; NDK standard library support must be confirmed. This integration is not release-ready. Include upstream runtime and GGML license notices and weight provenance in production installers before enabling this lane.

## AssetFurnace comparison

[AssetFurnace](https://assetfurnace.com/llms.txt) is a complementary reference implementation for multi-backend orchestration, cleanup, pixel-preserving projection, rigging, animation presets and per-output model-license provenance. It advertises Apple Silicon and NVIDIA Linux, limited Windows testing, Python and Blender for finishing; it is not an Android/ChromeOS dependency. Its MCP installation instructions are for local agent clients, not instructions to execute an installer in this app. Evaluate reusable algorithms separately, with license review and portable execution requirements; no AssetFurnace runtime, cloud service or weights have been added.
